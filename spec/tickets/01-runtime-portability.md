# Ticket 01: Runtime-portability decouple — un-pin Cadence from Claude Code

**Status:** TODO (revised 2026-06-13 after review — re-scoped: the coupling is template/skill *text*,
not script env-resolution)
**Repo:** cadence
**Depends on:** 00
**Source of truth:** `00-integration-design.md` (mapping table + correction), `spec/06-separation-of-concerns.md`,
`plugin/scripts/*.py`, `plugin/skills/*/SKILL.md`, `tests/conftest.py`.

## Goal

Make Cadence's executable layer run under any runtime with Python + bash + git, without changing
behaviour under Claude Code. Prerequisite for Pi driving Cadence (Tickets 02, 03).

## What review found (the re-scope)

The original ticket assumed the scripts read `${CLAUDE_PLUGIN_ROOT}` and proposed a
`CADENCE_PLUGIN_ROOT → CLAUDE_PLUGIN_ROOT → __file__` env-resolution order. **That code path does not
exist.** A grep of `plugin/scripts/*.py` shows **zero** runtime reads of the var; sibling scripts
already resolve via `Path(__file__).resolve().parent` (`start-setup.py`, `onboard-setup.py`,
`onboard-register.py`, `init-engagement.py`). So `python plugin/scripts/set-status.py` **already works
headless today**.

The real coupling is the **literal `${CLAUDE_PLUGIN_ROOT}` token emitted into agent-facing markdown** —
the `reference.md` template in `init-task.py`, the four `plugin/skills/*/SKILL.md` files, and a mirrored
copy in `tests/conftest.py`'s `make_task`. Under Claude Code the CC shell expands that token; under Pi
the method-pin (Ticket 03) tells the agent to use `$CADENCE_PLUGIN_ROOT` instead. The fix is about
**what string the skills/templates tell the agent to type**, not script internals.

### Confirmed coupling inventory (review-verified — keep exhaustive)

1. **`${CLAUDE_PLUGIN_ROOT}` token** in `init-task.py`'s `reference.md` template, all four `SKILL.md`
   files, and `tests/conftest.py` (`make_task`). ← the primary, agent-facing coupling.
2. **`.claude/tools/` runtime read** — `load-context.py` assembles the global-tools tier from
   `root/.claude/tools` and the skills reference it (`start/SKILL.md`, `onboard/SKILL.md`). Inert under
   Pi but bakes the CC dir name into the context payload; document it.
3. **`.claude/settings.json` + `.claude/tools/` scaffolding** generated by `init-engagement.py`,
   `init-class.py`, `init-task.py`. Inert under Pi; **keep emitting** (Cowork needs it).
4. **cwd assumption** (open-item #18, unbuilt): skills assume cwd = class/task dir and scripts walk
   *up* via `.absolute()`. A headless run sets cwd = the task dir (Ticket 02a forwards
   `cwd=/work/$CADENCE_TASK`); the walk-up then resolves correctly **iff `/work` is not a symlink**
   (`.absolute()` doesn't canonicalize — verify).
